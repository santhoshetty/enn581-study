## Formulas (slide image/text; no notebook for W12)
- Free space, p. 15: $$\mathcal{C}_{free}=\{q\in\mathcal{C}\mid q\cap\mathcal{C}_{obs}=\phi\}$$ q = configuration (point in C), C_obs = obstacle region in C, φ = empty set. Slide writes 𝒪 ∈ 𝒲 (workspace) and 𝒞_obs ∈ 𝒞 with ∈ (intended: subset).
- A* priority, p. 59: $$f(n)=g(n)+h(n)$$ g = "cost to arrive at node n"; h = "optimistic cost from node n to goal"; f = estimated total cost.
- Admissible, p. 61: $$h(n)\le d(n,goal)$$ never overestimates.
- Consistent, p. 61: $$h(n)\le d(n,m)+h(m)$$ for adjacent n, m; d(n,m) = edge cost.
- BFS complexity, p. 65: $$O(|V|+|E|)$$.
- Heuristics, p. 61: Euclidean, Manhattan, Zero (gives Dijkstra).

**Inflation (pp. 20–24).** Robot (blue) shrinks to a point; obstacle (red hatch) grows by the robot size (blue margin). Examples: L-shape (rounded margin), right triangle (rectangular robot gives polygonal margin). p. 24: "Twist and turn this 2D polygon past this other 2D polygon" becomes "Find a path for this point in 2D space past this augmented 2D polygon".

**Visibility graph (pp. 28–36).** "Find all non-blocked lines between polygon vertices, start and goal. Search the graph of these lines for the shortest path." Steps: lines from start and goal to all visible vertices and corners (p. 30); lines of sight from every obstacle vertex, including along edges (p. 31); continue/repeat (pp. 32–33); search (p. 34). Pictured shortest paths (red) touch obstacle corners. Reduced (p. 36): keep lines that "go around the object, or pass through the extremes"; lines through circled (red) concave points can be ignored "in certain cases".

**Voronoi (pp. 38–40).** Path follows curves equidistant from obstacles, start to goal; polygon obstacles give straight and parabolic segments.

**Cells (pp. 44–46).** Exact: vertical trapezoid cells plus adjacency graph. Approximate: uniform grid, cells touching obstacles blocked. Adaptive: big cells in open space, small near obstacles.

**PRM (p. 70, Short et al. 2016).** (a) learning phase: random sample ×. (b) local planner connects new sample to nearby roadmap vertices. (c) query phase: start and goal added. (d) graph search connects them (thick path).
**RRT (p. 74).** (a) tree grown from start towards goal. (b) planner generates q_rand, grows from nearest node towards it to create q_new. (c) tree rapidly explores free space. (d) terminates when a node is close to the goal; "common implementations will connect directly to the goal". p. 78: car, sample controls and choose the configuration closest to the target. p. 79: car RRT, yellow goal disc, orange path.

## Other slide facts
- p. 5, 7, 8: planning = given map, start, goal, find a trajectory respecting robot constraints. Inputs: geometry (map), kinematics (DOF, constraints), start and goal configurations. Outputs: continuous collision-free configuration sequence; report failure if none exists. Assumptions: expressive representation, known pose and goal, motion model; typically optimisation (min time/distance within constraints).
- p. 9 trends: classical mid-70s (exact models, no sensing); reactive mid-80s (no models, heavy sensing); hybrid 90s (models high-level, reactive low-level); probabilistic since mid-90s (models plus sensing, inaccurate both).
- p. 12 task space = frame where the task is performed (end effector, mobile robot). p. 14 C-space = generalised coordinates (joint parameters; position and orientation). p. 17 why C-space: nearby poses close, easy collision checks, abstraction, helps wraparound.
- p. 25: combinatorial = captures connectivity of C_free into a graph then search; sampling-based = collision detection to probe C-space incrementally.
- p. 35 visibility pros: shortest path, simple for polygons; cons: nodes/edges grow with polygons (dense = inefficient); path hugs obstacles.
- p. 38, 40 Voronoi: collision-free as far as possible from obstacles, maximises the closest distance; simple range-sensor control (sonar, laser); cons: short-range sensors may fail.
- p. 42 cells: divide, build adjacency graph, search cells containing start/goal, compute path within each cell.
- p. 48 graph search = least-cost problem on a directed graph; discretisation puts completeness at stake; feasibility seldom encoded. p. 49: deterministic BFS, DFS (uninformed), Dijkstra, A*, D* (informed); randomised PRM, RRT. p. 54 depth can be limited. p. 58 Dijkstra does not know the goal until it reaches it. p. 61 heuristic must be fast, close, admissible, consistent.
- p. 64 grids: resolution trade-off, connectivity set by grid shape, curse of dimensionality.
- p. 66 sampling: random points, connect nearby (straight lines), no explicit C_free/C_obs split, collision detector tests membership in C_free.
- p. 68 PRM 1996, RRT 1998. p. 69 framework: (1) G=(V,E) empty; (2) sample a point, add to V; (3) for new v pick near nodes, connect with local planner; (4) if collision-free add to E; (5) repeat from 2; (6) query start-goal connection.
- p. 71 PRM: build roadmap, then search (e.g. A*). p. 72 limits: holonomic assumption, narrow passages, unsuited to dynamic environments (roadmap made first). Strength: high-dimension problems (snake robots).
- p. 73 RRT: grow tree from start, dynamically feasible local paths, stop in goal region. p. 77: point robot assumes holonomic; robots may be non-holonomic.
- p. 80 complete = finds a collision-free path whenever one exists, else reports failure. Resolution complete = path wherever one exists at the chosen resolution. Probabilistically complete = path with high probability if it exists; may not terminate if none. p. 81: visibility graphs and Voronoi complete; BFS resolution complete; DFS not complete for infinite trees; PRM and RRT probabilistically complete (probability tends to 1 as samples tend to infinity).
