Week 12 · Planning algorithms

How does a robot find a collision-free route?

Motion planning turns “get from here to there without hitting anything” into a search problem. First squeeze the robot down to a point by working in configuration space. Then either build a graph of the free space and search it (BFS, DFS, Dijkstra, A*), or skip the explicit map and sample random points (PRM, RRT). Know what each method guarantees, what it costs, and be able to run Dijkstra and A* by hand.

Intuition first

Configuration space shrinks the robot to a dot

Walking a sofa through a door is hard because the sofa has size. Pretend instead the sofa is a dot and thicken the walls by the sofa’s reach. Then “can it pass?” is just “can a dot get through?”.

BFS is a ripple, Dijkstra is a ripple that counts distance

Drop a stone in a pond and the ripple reaches every point at the same number of steps. Dijkstra’s ripple instead advances by travelled cost, so it is the right ripple when roads have different lengths.

A* is Dijkstra with a compass

You still add up the distance walked so far (g), but you also add a guess of the distance left (h) and always follow the smallest total. If the guess is never too pessimistic about how short the rest is, you still arrive by the best route.

Sampling is throwing darts at the floor plan

Throw random darts (points), keep those that land on free floor, and join near ones with straight strings that do not cross a wall. PRM builds the whole web first and then searches it. RRT grows one tree outward from the start, like a plant seeking light.In the practical: Q2 asks for the web (PRM), Q3 for the plant (RRT).

1 · What planning means, and the framework pp. 4–9, pp. 25–26

Picture

Planning here means motion or path planning: given a map, a start and a goal, find a trajectory the robot can execute (p.5). It sits on top of everything earlier in the unit: kinematics tells you which motions are possible, trajectory generation (W5) smooths the route, control (W8–9) follows it.

Inputs (p.7): geometry of robot and obstacles (the map); kinematics of the robot (degrees of freedom, constraints); start and goal configurations. Output: a continuous sequence of collision-free configurations from start to goal, or a report of failure if none exists. Simplifying assumptions (p.8): the representation is expressive enough, we know where we are and where we want to go, we have a motion model, and the task is usually cast as optimisation (minimum time or distance within constraints).

The field moved from classical (mid-70s: exact models, no sensing), to reactive (mid-80s: no models, heavy sensing), to hybrid (90s: models at high level, reactive at low level), to probabilistic (since mid-90s: models plus sensing, both inaccurate) (p.9).

The framework (p.25): start from the continuous C-space, then discretise, because computers store digital things and standard graph-search algorithms then apply (p.26). Two families:

Combinatorial planningSampling-based planning
IdeaDescribe Cfree explicitly, capture its connectivity in a graph, search the graphUse a collision detector to probe C-space point by point; no explicit Cfree / Cobs split
Slide examplesvisibility graph, Voronoi, cell decomposition, grid + BFS/DFS/Dijkstra/A*PRM (1996), RRT (1998)
Completeness (p.81)visibility graph and Voronoi: complete; BFS: resolution complete; DFS: not complete on infinite treesprobabilistically complete
Completeness (p. 80)
  • Complete: finds a collision-free path whenever one exists and reports failure otherwise.
  • Resolution complete: discretises the space and returns a path wherever one exists at the chosen resolution. A gap narrower than a cell is invisible to it.
  • Probabilistically complete: returns a path with high probability if one exists, and may not terminate if none exists. As samples tend to infinity, the probability of finding a path tends to 1.
Exam recipe
  1. For “which planner?”, first ask: is the map known and polygonal (visibility graph, cells), is clearance wanted (Voronoi), is it a grid with costs (Dijkstra, A*), is the space high-dimensional or the robot non-holonomic (PRM, RRT)?
  2. For a completeness statement, always add the qualifier: “complete”, “resolution complete” or “probabilistically complete”.
  3. Never write “guarantees the shortest path” unless the method is on the list: visibility graph (for the polygon map), Dijkstra, or A* with an admissible heuristic.
  4. Sanity check: does the answer mention what the planner does when no path exists?
Trap: “PRM and RRT are complete” is false; they are probabilistically complete. “BFS is complete” needs “on a finite graph / at the grid resolution”. DFS fails on infinite trees because it can dive forever.

2 · Configuration space, Cfree, Cobs and inflation pp. 11–24

Picture

Task space is the frame where the task is performed, such as the end effector or a mobile robot’s body frame (p.12). Configuration space (C-space) is the set of generalised coordinates that completely describe the robot: joint parameters for an arm, position and orientation for a mobile robot (p.14). One robot configuration is one point in C-space.

The workspace obstacles map to a region Cobs in C-space; everything else is Cfree. Planning means finding a continuous curve inside Cfree from qstart to qgoal (p.15).

Why work there (p.17): nearby configurations are close together, collision checks and joining nearby poses become easy, one algorithm serves many robots (abstraction), and it handles wraparound for rotary joints.

Arm example (p.19): a planar 2-link arm among four rectangles. Each rectangle becomes a curved blob in the (θ1, θ2) plane, and the largest rectangle becomes a large region. The slide shows a vertical line at one θ1: the arm’s second joint can only avoid the blobs along that line.

Mobile robot example, inflation (pp. 20–24): shrink the robot to a point and grow each obstacle by the robot’s size. A circular robot gives a margin of constant width with rounded corners; a polygonal robot gives a polygonal margin. The problem “twist and turn this polygon past that polygon” becomes “find a path for a point past an augmented polygon” (p.24).

Derivation

Free space (p.15), with \(\mathcal C\) the C-space, \(\mathcal C_{obs}\) the obstacle region, \(\phi\) the empty set:

\[ \mathcal C_{free}=\{\,\mathbf q\in\mathcal C \mid \mathbf q\cap\mathcal C_{obs}=\phi\,\} \]
Slides vs textbook

p.15 writes “𝒪 ∈ 𝒲 or 𝒞obs ∈ 𝒞”. The obstacle set is a subset of the workspace or of C-space, so the symbol should be ⊂ (a set, not an element).

Inflation by a disc of radius \(r\) is the Minkowski sum of the obstacle with the disc. Each straight edge moves outward by \(r\), each convex corner becomes a circular arc of radius \(r\). For a convex polygon of area \(A\) and perimeter \(P\) the grown area is (Steiner formula)

\[ A_{grown}=A+P\,r+\pi r^{2} \]

For a square robot of half-side \(r\), aligned with the obstacle, the margin is a square one: a 2 × 2 m square grows to 3 × 3 m when \(r=0.5\) m.

Wraparound: a rotary joint angle \(q\) and \(q+2\pi\) are the same configuration, so C-space for revolute joints is a torus, not a flat rectangle. A path that leaves one edge of the plot re-enters at the opposite edge.

One workspace point can give several C-space points. For a 2-link arm with \(L_1=L_2=1\) m, the tip is at \((1,1)\) m for \(\mathbf q=(0^\circ,\,90^\circ)\) and also for \(\mathbf q=(90^\circ,\,-90^\circ)\) (the two inverse-kinematics branches). A single point obstacle at \((1,1)\) therefore blocks both configurations. A real obstacle has area and the whole arm (not just the tip) can hit it, so the blocked set is a curved region of C-space (the blobs on p.19). checked in checks/w12.py

Exam recipe
  1. State the robot’s configuration variables (joint angles, or x, y, θ).
  2. Replace the robot by a point; grow every obstacle by the robot’s radius (circle) or by its footprint (polygon).
  3. Draw Cobs and Cfree, mark qstart and qgoal.
  4. For a corridor of width \(w\) and robot radius \(r\), the point robot’s free width is \(w-2r\). If it is negative, the robot cannot pass.
  5. Sanity check: the inflated obstacle must contain the original and, for a disc robot, never be thinner than \(r\) on any side.
Worked example

Triangle with vertices (5,3), (6,3), (5,1) m, disc robot \(r=0.5\) m. Area \(A=\tfrac12\cdot1\cdot2=1\) m². Perimeter \(P=1+\sqrt5+2=5.236\) m (edges (5,3)–(6,3) = 1, (6,3)–(5,1) = √5, (5,1)–(5,3) = 2).

\(A_{grown}=1+5.236(0.5)+\pi(0.5)^2=1+2.618+0.785=4.403\ \text{m}^2\). checked

Corridor 1.0 m wide, robot radius 0.4 m: free width \(1.0-2(0.4)=0.2\) m for the point robot, so it fits. A robot of radius 0.55 m gives \(1.0-1.1\lt0\): it cannot enter. checked

Slide questions (pp. 22–23): “Where can the robot move in the vicinity of the obstacle?” (anywhere its centre stays outside the grown obstacle) and the same question for the point. Exam style: draw the inflated obstacle, or decide whether a gap is passable.

3 · Visibility graph and Voronoi diagram pp. 27–40

Picture

Visibility graph (pp. 28–36): “find all non-blocked lines between polygon vertices, start and goal, then search the graph of these lines for the shortest path”. Steps: draw lines from start and goal to every visible vertex (p.30); then lines of sight from every obstacle vertex, including along edges (p.31); repeat; search (p.34). The shortest path touches obstacle corners. The reduced graph (p.36) keeps only lines that go around an object or pass through its extremes; lines through concave corners can sometimes be dropped.

Pros (p.35): the shortest path is easy to find; simple for polygons. Cons: nodes and edges grow with the number of polygons (slow when dense); the path hugs obstacles as closely as possible.

Voronoi diagram (pp. 37–40): ignore optimality and keep as far from obstacles as possible; the path follows curves equidistant from the nearest obstacles and so maximises the closest distance. Pros: a robot with a range sensor (sonar, laser) can follow it with a simple rule, “maximise the sensor readings” (p.40). Cons: a short-range sensor may lose all obstacles and fail. With polygon obstacles the diagram has straight and parabolic segments.

Exam recipe
  1. Inflate obstacles first (visibility paths touch corners).
  2. List vertices: S, G and every polygon corner.
  3. Join every pair whose segment does not enter an obstacle interior (touching and sliding along an edge is allowed).
  4. Weight edges by Euclidean length; run Dijkstra or A*.
  5. Sanity check: the result is no longer than any other route you can sketch, and only bends at obstacle corners.
Worked example

Practical Q2 map, start S = (1.5, 1.5), goal centre G = (9, 9). The straight line S–G is the diagonal \(y=x\), which passes through the rectangle (6,6)–(8,8), so it is blocked. Going round the rectangle’s corner (8,6): \(|S-(8,6)|=\sqrt{6.5^2+4.5^2}=7.906\), \(|(8,6)-G|=\sqrt{1^2+3^2}=3.162\), total 11.068. To the edge of the goal disc (radius 1) subtract 1: 10.068. The corner (6,8) gives the same length by symmetry about \(y=x\). checked

Typical short question: “which method maximises clearance?” (Voronoi) and “which gives the shortest path but hugs obstacles?” (visibility graph). Trap: “Voronoi gives the shortest path”.

4 · Cell decomposition pp. 41–46

Picture

Divide free space into simple connected cells, build an adjacency (connectivity) graph (one node per cell, an edge when two cells touch), find the cells containing start and goal, search the graph, then compute a path inside each cell (p.42). Three flavours (pp. 44–46):

TypeHowTrade-off
Exactvertical trapezoid cells that exactly cover Cfree, plus adjacency graphno information lost; harder to build
Approximateuniform grid; any cell touching an obstacle is blockedsimple; resolution complete only; can lose narrow gaps
Adaptivebig cells in open space, small cells near obstaclesfewer cells than a uniform grid at the same detail

The uniform-grid version is what the rest of the week searches (section 7 onward).

Explain-style: contrast exact and approximate decomposition. Keywords: exact = complete; approximate = resolution complete, resolution is a trade-off between losing narrow passages and search time (p.64).

5 · Graph search, BFS and DFS pp. 47–55

Picture

Graph search solves a least-cost problem between two states on a (directed) graph (p.48). The graph is a discrete picture of the world: nodes are places (cells, vertices), edges are moves with a cost. Two limits: discretising the state space puts completeness at stake, and the feasibility of paths (turning limits and so on) is seldom encoded.

The slide sorts the methods (p.49): deterministic uninformed BFS and DFS, deterministic informed Dijkstra, A*, D*; randomised PRM and RRT. The bracket on the slide is ambiguous about Dijkstra; conventionally Dijkstra is uninformed (it is A* with h = 0), and A* is the informed one.

  • BFS (p.50): keep a first-in-first-out queue. Expand the oldest node, add its unseen neighbours at the back. Nodes are reached in order of number of edges from the start, so BFS returns the path with the fewest edges. That is the cheapest path only when every edge costs the same. Cost \(O(|V|+|E|)\) (p.65); resolution complete.
  • DFS (p.52): keep a last-in-first-out stack (or recurse). Follow one branch as deep as it goes, back up only at a dead end. Uses little memory but finds a path, usually a long one, with no cost guarantee. Not complete on infinite trees. The depth can be limited (p.54).

The grid pictures (p.51, p.53) show the contrast: BFS floods outward as an even front and the path found is short; DFS wanders and the path is long and winding.

Exam recipe
  1. State the tie-break rule (for example alphabetical) before you start; the slides do not give one.
  2. BFS: write the queue after each pop. Mark a node seen when it is added so it is never added twice.
  3. DFS: write the stack (or the recursion) after each step; go to the first unvisited neighbour.
  4. Stop when the goal is popped. Read the path back through parent pointers.
  5. Add up the edge costs yourself. BFS counts edges, not cost.
Worked example (worked by us, verified by script)

The slide’s graph (p.56): start A, goal K, edges A–B 10, B–E 9, A–C 6, C–F 5, F–H 7, H–J 4, J–K 3, A–D 8, D–G 9, F–G 3, G–I 7, I–K 5. The slide (pp. 50, 52) draws the graph unweighted and gives no answer, so the following uses our tie-break: neighbours in alphabetical order.

The best path costs 25 (section 6). Neither BFS (29) nor DFS (26) is cost-optimal. checked

Typical question: “which path does BFS return?” or “which finds the shortest path in a graph with unequal costs?”. Trap: BFS is optimal only with equal costs. A DFS answer depends on neighbour order, so write your order down; a different order gives a different (still valid) path.

6 · Dijkstra’s algorithm pp. 56–58

Picture

Dijkstra (1959) “searches outwards in order of cost from the start” (p.56). It always expands the node with the smallest past cost \(g\). Because edge costs are not negative, once a node is expanded no cheaper way to it can appear later, so its \(g\) is final. The slide’s table (p.57) is blank; its rows are past cost and parent node.

The weakness (p.58): it “doesn’t really know the goal exists until it reaches it”, so it expands nodes in every direction. The slide asks: can we guide the search toward the goal without breaking the rule that a node is accepted only with its lowest cost of arrival? That is A*.

Algorithm

Keep an open set (discovered, not yet expanded) with tentative costs, and a closed set (expanded, cost final). Start: \(g(\text{start})=0\).

  1. Pop the open node \(n\) with the smallest \(g\) (ties: alphabetical). Move it to closed.
  2. If \(n\) is the goal, stop.
  3. For each neighbour \(m\) of \(n\) not in closed, with edge cost \(w\): if \(g(n)+w\lt g(m)\) (or \(m\) is new), set \(g(m)=g(n)+w\), parent\((m)=n\), and put \(m\) in open (this is relaxation).
  4. Repeat. Trace the parents back from the goal.

Correct only for non-negative edge costs. Dijkstra is A* with \(h=0\).

7 · A* and heuristics pp. 59–62

Picture

A* is a “focused search that prioritises searching towards the goal, exploiting some knowledge about it” (p.59). Each node carries two numbers: the past cost \(g(n)\) (the slide’s blue arrow, A to D = 8, “cost to arrive at node n”) and an optimistic cost to go \(h(n)\) (the red arrow, D to K = 13, “optimistic cost from node n to goal”). A* expands the open node with the smallest sum.

Derivation \[ f(n)=g(n)+h(n) \qquad (\text{p.59}) \]

\(g(n)\): cost of the best path found so far from the start to \(n\). \(h(n)\): estimated cost from \(n\) to the goal. \(f(n)\): estimated total cost of a path through \(n\). A* = Dijkstra with the priority \(g\) replaced by \(f\); stop when the goal is expanded.

What a good heuristic needs (p.61): fast to compute, reasonably close to the real cost, admissible and consistent. With \(d(n,\text{goal})\) the true cheapest cost from \(n\) to the goal and \(d(n,m)\) the cost of the edge between neighbours \(n\), \(m\):

\[ \text{admissible: } h(n)\le d(n,\text{goal})\ \ \forall n, \qquad \text{consistent: } h(n)\le d(n,m)+h(m)\ \ \forall \text{ neighbours } n,m \]

Admissible means never overestimates (note the non-strict \(\le\): \(h=d\) is allowed). Consistent is the triangle inequality: the estimate may not drop by more than the edge you walked. Consistent \(\Rightarrow\) admissible (given \(h(\text{goal})=0\)), but not the other way round. Typical choices on a grid: Euclidean distance, Manhattan distance, or zero (which turns A* into Dijkstra).

  • Admissible h keeps A* optimal: if \(h\) never overestimates, no better route can hide behind a node whose \(f\) is too high.
  • Consistent h additionally makes the popped \(f\) values non-decreasing and means a closed node never needs re-opening. The lecture asks for both; strictly, admissibility gives optimality with re-opening, and consistency is what lets you use a simple closed set.
  • Overestimating h can send A* the wrong way: it returns a path that may not be optimal.

Comparison (p.62): on one grid with a wall, A* took 277 operations, BFS 1413, Dijkstra 1378 (source on the slide: PathFinding.js visualiser). So A* did about \(1378/277=4.97\) times fewer operations than Dijkstra. checked The figure comes from one demo; do not quote it as a general ratio.

Exam recipe
  1. Write \(h\) beside every node. Check admissibility: compare each \(h(n)\) with the true remaining cost (find it by inspection or a backward Dijkstra).
  2. Check consistency edge by edge, in both directions where \(h\) differs: \(h(n)\le w+h(m)\).
  3. Run the table: pop the smallest \(f=g+h\) (tie: smaller \(h\), then alphabetical; say so). Relax neighbours with \(g(n)+w\).
  4. Stop when the goal is popped. Trace the parents. Report order, path, cost.
  5. Sanity check: \(f(\text{goal})=g(\text{goal})\) = path cost; no open node should have \(f\) below it if \(h\) is admissible; unexpanded nodes (E here) are the saving over Dijkstra.

8 · Grid-based graphs and the curse of dimensionality pp. 63–65

Picture

A grid turns C-space into a graph: each free cell is a node, and edges join neighbouring cells. Problems (p.64): it is hard to choose a resolution that is fine enough to keep valid solutions (obstacles inflated by the grid size) yet coarse enough to solve quickly; connectivity is dictated by the grid shape; and in higher dimensions grids suffer from the curse of dimensionality.

9 · Sampling-based planning: PRM and RRT pp. 66–79

Picture

Main idea (p.66): instead of dividing C-space into cells, pick random points and try to connect them. Much of the space is usually free, and two nearby points can be joined by a simple path such as a straight line. We abandon the explicit split of C into Cfree and Cobs; a collision detector just says whether a picked point is in Cfree. This is “more efficient than grid-based” and needs no explicit obstacle representation (p.83). The two classics: PRM (1996) and RRT (1998) (p.68).

General framework (p.69): (1) start with an empty graph \(G=(V,E)\); (2) sample a random point and add it to \(V\) (needs a sampler); (3) for each new vertex \(v\), pick ‘near’ vertices (needs a distance function) and try to connect them with a local planner; (4) if the local path is collision-free (needs a collision detector) add it to \(E\); (5) repeat from 2 until satisfied; (6) query: find a connection from start to goal.

PRM (pp. 70–72), two phases: learning (a random sample is generated; a local planner connects it to nearby roadmap vertices) then query (start and goal are added; a graph search such as A* connects them through the roadmap). Strengths: conceptually simple; solves high-dimensional problems (snake robots). Limits: assumes holonomic motion (any direction possible); can fail on a narrow passage; not suited to dynamic environments because the roadmap is built first and then searched.

RRT (pp. 73–79): a tree (a special graph) grown from the start. Each iteration: draw a random configuration \(q_{rand}\); find the nearest tree node; grow from it a short step towards \(q_{rand}\) to create \(q_{new}\); add it if collision-free. It terminates when a node is in the goal region; “common implementations will connect directly to the goal” (p.74). The tree rapidly explores free space (p.74); the usual reason, not stated on the slides, is that big empty regions are the nearest region to most random samples, which pulls the tree outward. The local paths are meant to be dynamically feasible.

Non-holonomic robots (pp. 77–79): straight lines in C-space assume a point that can move in any direction. A car cannot. The fix on p.78 is to sample controls (steer and speed) and keep the resulting configuration closest to the target, so every edge is a drivable motion. The summary says RRT can be used with non-holonomic systems (p.83).

Building blocks (practical Q2 a–g)
  • Sampler: uniform random point in \([0,10]^2\). The chance that one uniform sample lands in the goal disc (radius 1, area \(\pi\)) is \(\pi/100=0.0314\); the expected number of samples is about \(100/\pi\approx32\). checked
  • Point in polygon (ray casting): shoot a ray from the point in the \(+x\) direction; count edges it crosses. Odd means inside. An edge counts when its end points straddle the ray’s \(y\) and the crossing \(x\) is to the right of the point.
  • Segment against polygon: a segment \(\overline{ab}\) crosses an edge \(\overline{cd}\) if \(c,d\) are on opposite sides of line \(ab\) and \(a,b\) are on opposite sides of line \(cd\), using the sign of the orientation \((b-a)\times(c-a)\). Test all polygon edges. A segment with both end points free can still cross a polygon.
  • Nearest vertex: smallest Euclidean distance \(\|q-v\|\).
  • Goal test: \(\|q-G\|\le1\) (the goal is a disc).
Exam recipe
  1. PRM: sample \(N\) points, discard those inside obstacles; connect each to its \(k\) nearest vertices (or all within radius \(r\)) if the straight segment is free; add S and G the same way; run A* or Dijkstra on the graph.
  2. RRT: tree \(=\{S\}\). Loop: sample \(q_{rand}\) (sometimes the goal); nearest node \(q_{near}\); \(q_{new}=q_{near}+\delta\,(q_{rand}-q_{near})/\|q_{rand}-q_{near}\|\); if the segment \(q_{near}\to q_{new}\) is free add it with parent \(q_{near}\); stop when \(\|q_{new}-G\|\le1\).
  3. State the guarantee: probabilistically complete; the path is usually not shortest; no termination guarantee if no path exists.
  4. Sanity check: every edge in your path passed the segment test, the first node is S and the last is inside the goal disc.
Worked example (worked by us, verified by script)

Typical: “PRM or RRT for a car with turning limits?” (RRT with sampled controls). “Which cannot cope with a changing map?” (PRM: roadmap built first). “What does ‘probabilistically complete’ mean?” (probability of finding a path tends to 1 as samples tend to infinity; may run forever if none exists). (iv) Only probabilistically complete; the probability tends to 1 as samples grow, and it may never terminate if there is no path. (v) BFS minimises the number of edges (29 vs the optimum 25 on the slide graph). (vi) The condition is non-strict: \(h(n)\le d(n,\text{goal})\); \(h=d\) is admissible (and h(K) = 0).

Mini-quiz

Q1concept

Which heuristic turns A* into Dijkstra’s algorithm, and what does that tell you about A*?

Answer

\(h(n)=0\) for all nodes (the “zero” heuristic on p.61). Then \(f=g\), and A* expands in order of past cost exactly like Dijkstra. So A* is Dijkstra plus guidance; a good \(h\) only reorders the search toward the goal.

Q2calculate

A 4-connected 100 × 100 grid: how many edges, and what is \(|V|+|E|\) for BFS?

Answer

Horizontal edges \(100\cdot99=9900\), vertical \(99\cdot100=9900\): \(|E|=19\,800\). \(|V|=10\,000\), so \(|V|+|E|=29\,800\). checked

Q3spot the error

“PRM builds a tree from the start and stops when it reaches the goal, so it is good for dynamic environments.” What is wrong?

Answer

That describes RRT. PRM builds a roadmap (a graph) first, then answers queries by graph search; because the roadmap is made before it is used, it is not suited to dynamic environments (p.72).
